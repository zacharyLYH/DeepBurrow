# M12 — Refresh token simplification

## Why change

Today refresh tokens rotate into a **new row every 15 min** and lean on an `auth_sessions` table to group them. That means ~96 rows/day/user, a join on every refresh, and a second table. Two real problems:

- **Row bloat.** Refresh runs whenever the 15-min access token expires (api.ts:27). One row per refresh adds up fast with no cleanup job.
- **Password-era leftover.** `revokeAllSessions` (db.ts:521) is dead code from the old "log out all devices" flow. Nothing calls it.

We also want **attacker-first damage control**: if a refresh token is stolen and the attacker uses it before the real user, the user must be able to burn the attacker's session — not get locked out.

## Design

Replace the `auth_sessions` + rotating-rows model with **one `refresh_tokens` row per login**, using an `id.secret` token.

- Cookie `db_refresh` holds `id.secret` — `id` is a UUID handle, `secret` is random bytes.
- DB stores `sha256(secret)` only. Raw secret never touches the DB.
- The `id` half lets the server find the row **even when the secret is stale** — that is what makes "wipe on mismatch" possible.

### Flow (`/auth/refresh`)

```
raw = readRefreshCookie(c)                 // "id.secret"
[id, secret] = raw.split(".")
row = SELECT * FROM refresh_tokens WHERE id = id

if row && sha256(secret) === row.token_hash && !row.revoked_at && row.expires_at > now:
    newSecret = random()
    UPDATE refresh_tokens SET token_hash = sha256(newSecret) WHERE id = id
    setCookie("id." + newSecret)           // rotate
    issue new access token
else:
    DELETE FROM refresh_tokens WHERE id = id   // or revoked_at = now (audit trail)
    rejectAuth(c)                              // session exposed
```

### Why this beats a version counter

`sha256(secret)` compare replaces "compare version integer" — same power, no JWT for the refresh token, no version math. Access token stays a stateless JWT (guard unchanged).

### Attacker-first, handled

1. Attacker steals `X.secret0`, refreshes → row X now holds `sha256(secret1)`.
2. User sends `X.secret0` → id `X` found → hash mismatch → **wipe row X**.
3. Attacker's `X.secret1` → row gone → dead. User re-logs in via email code.

Residual: the attacker's already-issued access token lives ≤15 min, because `guard` never checks the DB. Short TTL is the only lever without going stateful. Real prevention stays httpOnly + Secure + SameSite + CSRF origin check.

## Schema change

```sql
-- drop
DROP TABLE auth_sessions;
DROP TABLE refresh_tokens;

-- add
CREATE TABLE refresh_tokens (
  id          TEXT PRIMARY KEY,          -- public handle (UUID), inside the cookie
  user_id     TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token_hash  TEXT NOT NULL,             -- sha256(secret)
  created_at  INTEGER NOT NULL,
  expires_at  INTEGER NOT NULL,
  revoked_at  INTEGER
);
CREATE INDEX refresh_tokens_by_user ON refresh_tokens(user_id);
```

`used_at` and `session_id` are gone — rotation is now the hash overwrite, and revocation is per row.

## Code touch points

- `security.ts` — drop `signRefresh`/`verifyRefresh` (refresh no longer a JWT). Keep `signAccess`/`verifyAccess` and `digest`.
- `db.ts` — rewrite `refreshRecord`, `consumeRefreshToken`, `appendRefreshToken`, `revokeSession`, `createSession` into: `createRefreshToken`, `findRefreshToken(id)`, `rotateRefreshToken(id, newHash)`, `revokeRefreshToken(id)`. Delete `revokeAllSessions`.
- `auth.ts` — `issueRefresh`/`issueSession` write the `id.secret` cookie instead of a signed JWT.
- `routes/auth.ts` — `/refresh` runs the hash-compare-or-wipe flow; `/logout` revokes by `id`.
- `tests/auth.spec.ts` — update the rotation/replay/expiry cases to the new cookie + wipe semantics.

## Edge cases

- **Concurrent refresh (two tabs).** Both send `X.secret0`; one rotates, the loser's hash no longer matches → wipe. Both re-login. Rare, safe, recoverable. Optional fix: cross-tab lock (`navigator.locks`).
- **Griefing.** `id` is an unguessable UUID and httpOnly (JS can't read it), so an attacker can't wipe someone else's session by guessing ids.
- **Expiry is now absolute** — one TTL, row expires once. Pick it (30 days is fine).
- **Cleanup.** Delete expired/revoked rows occasionally. Trivial now, not 96/day/user.

## Exit

`auth_sessions` gone; one `refresh_tokens` table with `id.secret` rotation; replay and attacker-first both revoke the row; no new access-token-per-refresh beyond what already happens; `npm run lint` clean; auth E2E green.
