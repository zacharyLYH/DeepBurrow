# M8 — Burrow navigation and visible prompts

## Burrows

- A user can own and switch between multiple burrows. List only the signed-in user's burrows.
- API: `GET /burrows` lists owned burrows; `POST /burrows` creates one; `PATCH /burrows/:id` can rename it while retaining viewport updates.
- Add a collapsible, shadcn-style sidebar: expanded burrow list on desktop, fully hidden when collapsed, and a mobile sheet/drawer.
- Sidebar supports creating a burrow and renaming one. A page-plus action opens a modal that takes a question or link; on send, the burrow is created and the canvas opens on the pending root card. An empty canvas offers the same action in the middle.
- Burrow titles are trimmed, 1–80 characters, and unique per user case-insensitively. Same title is allowed for different users. Reject duplicate create/rename with a clear conflict; do not silently rename.
- Keep the last selected burrow on the current device, scoped by user. On first use, select the account's initial burrow.
- Burrow deletion is out of scope. Existing user ownership checks apply to listing, creating, renaming, and loading burrows.

## Prompt in each card

Show each node's originating question as a Markdown blockquote above the answer; use the preset label when no question was entered. Show selected text as separate context. Use persisted `origin` so this survives reload and retry. Include the prompt in Copy as Markdown and canvas export. This is presentation only; it does not change model context.
