# M11 — Installable app and push notifications

## Install and offline

- Add a manifest, service worker, and app icons derived from `apps/web/public/deepburrow_logo.png`; serve over HTTPS. Show platform-specific install steps; browsers handle the install UI.
- On the M10 landing page, add concise iOS/iPadOS and Android instructions for adding the PWA to the Home Screen; use platform/browser-appropriate steps and note that menus can vary.
- Cache versioned static assets only. Never cache authenticated API responses, burrow data, or credentials. Offline, explain that sign-in, burrow loading, asks, and completion delivery require a connection; do not queue asks.
- Update safely: service-worker changes apply on the next refresh or reopen. On iOS/iPadOS, explain that push requires adding the site to the Home Screen.

## Push

- Check for a push subscription for this PWA installation and signed-in user. If absent, show dismissible Enable/Later prompt. Ask browser permission only after Enable.
- On enable, register this device, then send a test push; show it even while the app is visible and confirm only after service-worker receipt. Settings can toggle this device off; other devices remain subscribed.
- Send completion push only after the agent loop, validation, persistence, and completion event. Never notify for intermediate steps. Show generic text without prompt/answer content.
- Link with `burrowId` and `nodeId`; click opens that burrow and focuses the node, or just the burrow if the node is unavailable.
- Handle unsubscribe, sign-out, renewal, expired endpoints, and multiple devices without crossing user accounts.

## VAPID and startup

- Read `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, and `VAPID_SUBJECT` from `apps/api/.env`; only the public key reaches the client.
- Update `make start` to check `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, and `VAPID_SUBJECT` in `apps/api/.env`. Generate and save a matching key pair when either key is missing; prompt for subject when missing. Preserve complete existing values, never create root `.env`, and never log secrets. Key rotation invalidates subscriptions.

## E2E

- Use a mock push relay, never real VAPID keys or external services.
- Test opt-in, test-push receipt, completion-only timing, visible suppression, click-through, unsubscribe/expiry, multiple users/devices, install metadata, service-worker updates, offline messaging, and denied/unsupported permissions.

**Exit:** install and push work where supported; subscriptions remain user/device scoped; completion push is reliable, private, and covered by mock-relay E2E.
