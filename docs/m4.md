# M4 — Research loop

Make the burrow dig by itself: `plan → (compose → judge)* → summarize`. Every path ends answered, stopped or failed. No search executor yet (M6) — rounds run on notes and scripted questions.

**Exit test:** scripted model forces 3 rounds and each stop condition, call counts asserted; FE progress advances, no card left pending.

## Loop

- `judge` returns `{ done, suggestedQuestions }`; non-done routes back to `compose`.
- Stop on `judge` done or after 3 rounds. No token cap (it would cut a thought mid-way). "No new URL" waits for M6.
- `compose` = lineage + ask + queue[0]; `summarize` unchanged from M3.
- `State.tokens` = estimated completion tokens (chars/4), round log only, never enforced.
- `suggestedQuestions` is the live queue: `plan` seeds, `compose` eats the first, `judge` resolves and appends. DB owns lineage; the queue never persists.
- One JSON log line per round: `{ nodeId, round, openQuestion, tokens, verdict }`. Console only.

## Progress

`node.progress { line }` before each model call and after a done verdict. Human copy (the question, what's being checked), never `Round N`. Ephemeral: SSE for live UX only, never on `Node`, never in the DB. FE holds it in local state, appends under the card, clears on first token. After reload there's no history — skeleton only.

## Persistence

Two writes: `pending` at start, terminal (`answered | stopped | failed`) at settle. Nothing between. The start row makes a refresh show the in-progress card; the settle row is the answer. A crash mid-run leaves a pending row; reattaching settles it `stopped`.

## Resume

A run survives refresh. Keep it, re-point the pipe, heal on terminal.

- Live runs: `Map<nodeId, { abort, subscribers }>` in `runs.ts` — the running `graph.stream`, its `AbortController`, attached SSE writers. The only non-row state; lost on restart.
- `POST /ask` starts or retries a run. `GET /nodes/:id/stream` reattaches to a live run, or replays a row that already settled. `POST /nodes/:id/cancel` stops it.
- Refresh re-fetches the burrow and renders pending nodes as skeletons, then opens the node's stream.
- No snapshot, no seq, no replay. `node.done` / `node.error` carry the full node, so missed tokens self-heal at the end. Write the row, then send it — no race.
- Lifecycle is explicit (`pending → terminal`), driven by done / error / timeout / cancel. Tokens never change status; they just fill the body. Never reads progress.
- Timeout → `failed`. Cancel → `stopped`; retry starts a fresh run on the same id. A crash leaves a pending row that the next attach settles `stopped`.

## Contract

```
node.progress  { nodeId, line }     // live only
node.done      { nodeId, node }     // full settled node
node.error     { nodeId, node }     // full failed node
```

`node.pending | meta | token` unchanged. `Node` unchanged — no `progress` field.

## FE

- Progress lines appended under the pending card, `text-xs` muted; clear on first `node.token`.
- On `node.done | node.error`, replace the local node with `event.node` (repairs dropped tokens).
- Stopped/failed cards show `error` / status; no stored progress line.
- No new surfaces.

## Tests

Unit: 1 round ends on done; 3 rounds hit the cap; call counts per stop condition; progress has no round numbers and is never persisted; bad judge JSON → failed, not stuck.

Playwright: progress advances then clears; every ask ends terminal; a `pending` row exists mid-run and settles; kill API mid-run → pending row, next attach settles it; reload mid-run reattaches and finishes without a second run; reattach after a dropped connection still yields the full answer; `FAKE_VERDICT=done` stops after one round; timeout → failed; cancel → stopped, retry → answered.

## Non-goals

No search, URL filtering, notes, settings, auth, ⌘K, PWA, real model, sibling loops, or cancel-per-round (cancel is whole-run). M5 onward.
