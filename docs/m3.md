# M3 — Backend core + FE cutover

Give the tree a spine. Mock SSE dies; the FE talks to a real API that runs a real (fake-model) graph and persists to SQLite.

**Exit test:** pure `plan/compose/summarize` replay the same state; Playwright vs real API — ask → stream → answered, reload persists, retry reuses the node, no mock SSE in the app path.

## Deliver

- **API server.** `apps/api` becomes the real server: Hono on Node, JSON reads, SSE write, static nothing. `npm run api` boots it on `:8787`; Vite proxy stays `/api → :8787`.
- **Repo.** `node:sqlite` `DatabaseSync`, migrations from `db/migrations` applied on boot, `PRAGMA foreign_keys = ON`. File at `./data/deepburrow.db` locally, `/data/deepburrow.db` in Docker. Functions: `getBurrow` (burrow + nodes), `insertNode`, `updateNode`, `getNode`.
- **Seed.** Boot creates the demo user + burrow from `fixtures.ts` if empty. One user until M7 auth.
- **Graph.** LangGraph.js (`@langchain/langgraph`). One compiled `StateGraph` over the `State` type: `START → plan → compose → summarize → END`, linear this milestone. Nodes are pure `(state) => state`; model and repo are adapters bound when the graph is built. No search, no judge loop (M4).
- **Fake model.** `Model` = `{ complete(messages): Promise<string> }`. Deterministic: same state → same JSON for `plan`, same header + body for `summarize`. Real OpenAI-compatible adapter lands M7.
- **SSE.** Same event list as M0, emitted from the summarize stream. Persist on `done` and on abort. Retry = new stream, same node id, text cleared.
- **FE cutover.** `useBurrow` loads `GET /api/burrows/:id`, owns the nodes, no fixture import in `app.tsx`. `streamAsk` keeps its shape; only the URL and payload change. One load error surface, retryable.
- **Mock SSE archive.** Stays importable for `contract.spec.ts`; removed from `playwright.config.ts` webServer.

## Stack

- **Hono** on Node for HTTP. `node:http` would do, but Hono gives routing and middleware for M7 auth.
- **LangGraph.js** for the graph. It is the thing we wanted for the loop in M4, so build M3 on it rather than a hand-rolled chain we throw away.
- **`node:sqlite`** (`DatabaseSync`) for storage, raw SQL, no ORM. Node 26 ships it, the contract suite already uses it, and there is no native build. Swapping to `better-sqlite3` later is mechanical because the SQL is the same.

## Endpoints

```
GET  /api/burrows/:id            → { burrow, nodes }        // ordered by created_at
POST /api/ask                    → SSE stream
     { nodeId?, parentId, ask, origin }
GET  /api/health                 → 200                      // playwright readiness
```

`nodeId` present = retry: same row, truncate text, rerun. Absent = server mints and emits it on `node.pending`.

## Graph state

```
plan      → suggestedQuestions[], round = 1, notes = ""
compose   → notes += lineage + ask          // no search blob: notes only, no suggested question fetch
summarize → title, sources[], followups[], answer    // parses header via parseHeader
```

State is a LangGraph `Annotation.Root` mirroring `State` in `packages/types`: `notes` appends, every other channel replaces. Nodes never touch the DB or the network — each is a factory that closes over the `Model` adapter, so a test can pass a fake and replay the graph with no I/O.

```
const graph = new StateGraph(StateAnnotation)
  .addNode("plan", plan(model))
  .addNode("compose", compose(model))
  .addNode("summarize", summarize(model))
  .addEdge(START, "plan")
  .addEdge("plan", "compose")
  .addEdge("compose", "summarize")
  .addEdge("summarize", END)
  .compile();
```

One ask = one `graph.stream(state, { streamMode: "custom" })`. `compose` is a single model call in M3; `suggestedQuestion` bookkeeping is written but never acted on — M4 turns it into a loop by adding `judge` and the conditional edge. Prompts are rebuilt from `markdown` + lineage every call; only completions persist.

Lineage = recursive CTE up `parent_id`, root → node. Siblings never enter context.

## Streaming

- `plan` and `compose` run before the first byte; the client sees `node.pending` immediately.
- `summarize` returns header + body in one string. It splits with `parseHeader` and emits `{type:"node.meta"}` and `{type:"node.token"}` through the LangGraph writer (`config.writer`); the Hono handler maps writer payloads 1:1 onto SSE events. Header never reaches the client body.
- Sources are trusted verbatim this milestone — no search blob to validate against until M6.
- Client disconnect mid-stream: keep partial markdown, status `stopped`, no error event.
- Model or repo throw: `node.error` with one line, row saved as `failed`.

## Tests

Unit (existing Playwright runner, no browser, same as `contract.spec.ts`):

- Each node: same state in → same state out. No I/O, no clock, fake model.
- Replay: fixture state through the compiled graph twice → identical answer, sources, followups, and identical writer events.
- Repo: insert → update → get round-trips JSON columns; lineage CTE returns root → node.

Playwright vs real API:

- Ask from a card → answered, title, sources, chips.
- Reload page → same cards, same statuses, same text.
- Retry after a forced model failure → same node count, recovers.
- Abort mid-stream → partial text kept, `stopped`.
- App requests only `/api/*`; no `x-mock-scenario` anywhere.

## Non-goals

No search, no judge loop, no caps, no real model, no auth, no settings, no notes, no ⌘K, no PWA. No new card surfaces — FE work is wiring only. M4 onward.

## Decisions to confirm

- **No `judge` yet.** A fake model can fake a loop, but a loop with no search has nothing to loop over. Linear graph now, `judge` in M4 with caps and logs.
- **Persist `stopped`.** Stopped cards are real answers; reload should not resurrect them as streaming.
- **LangGraph dependency size.** `@langchain/langgraph` pulls `@langchain/core`; both stay in `apps/api` only, so the web bundle is unaffected.

## Order

1. Repo + migrations + seed; Hono app; `GET /api/burrows/:id` returns the fixture.
2. `Model` adapter + LangGraph `plan/compose/summarize` + replay test.
3. `POST /api/ask` SSE from the graph writer, persistence on done/abort/error.
4. FE cutover: load, stream, retry, stopped.
5. Failure path + Playwright suite; retire mock from webServer.
