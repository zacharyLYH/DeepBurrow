The spine works: ask → loop → stream → persist. M5 closes the gap between our card-first build and the reference in `~/Desktop/rabbithole`: canvas behavior, card actions, chrome, presets, provenance, and content rendering. Expanded reader/trail stays dropped (README). M5 also adds the small graph endpoints needed to make the canvas durable (rename, delete, layout). Renderers ship now and get real content when the model prompt lands in M7.

## Renderer choices

Pick open formats with a mainstream renderer; keep the DB storing raw Markdown.

| Content | Format / standard | Library | Why | Fallback |
|---|---|---|---|---|
| Markdown | CommonMark + GitHub Flavored Markdown | `react-markdown` + `remark-gfm` | README already prescribes `react-markdown`; GFM is the widest-supported superset | plain text |
| Tables, task lists, strikethrough, autolinks | GFM | `remark-gfm` | One plugin covers all four | plain text |
| Math | LaTeX | `remark-math` + `rehype-katex` + `katex` | Fast, SSR-safe, same choice as the reference | raw `$…$` |
| Diagrams | Mermaid (open-source text DSL) | `mermaid` | Reference parity; fenced source stays readable when rendering fails | code block + inline error |
| Code | Fenced code + info string | `highlight.js` | Reference parity, broad language coverage, small integration | plain `<pre>` |
| Links | GFM autolink/link | `react-markdown` defaults | Safe by default; open in new tab with `rel="noreferrer"` | text URL |
| Images | GFM image | `react-markdown` + lightbox | Same parser; click to enlarge | alt text |

Mermaid is an open-source DSL, not a standards-body spec; Graphviz DOT is the formal alternative but less common in LLM output and code blocks. Mermaid matches the reference, so it wins.

Rules:

- **No raw HTML.** Do not add `rehype-raw`. Unknown/unsafe URLs render as text.
- **Streaming-tolerant.** Render partial Markdown on every token without throwing; incomplete fences/tables degrade to text until closed.
- **Lazy-load heavy renderers.** KaTeX CSS and Mermaid load on first use, not on first paint.
- **Mermaid** renders client-side after mount; keep the source block copyable and show a one-line error if parsing fails.
- **Copy buttons** copy the raw source, not highlighted DOM.
- **New deps:** `react-markdown`, `remark-gfm`, `remark-math`, `rehype-katex`, `katex`, `mermaid`, `highlight.js`. Split KaTeX/Mermaid/highlight into lazy chunks so first paint does not pay for them.
- **M7 prompt contract** must ask the model for GFM, fenced code with language, `$…$`/`$$…$$`, and ```mermaid fences. The renderer is testable now with fixtures.

## M5 graph additions

The only backend work in M5. Everything else uses existing routes.

| Change | Shape |
|---|---|
| `nodes.position_x`, `nodes.position_y` | Flow coordinates, written on drag stop and tidy |
| `burrows.viewport` | JSON `{x,y,zoom}`: one camera per burrow, shared by every device |
| `users.settings` | JSON: theme, reading size, both preset sets, auto-tidy + grace |
| `nodes.deleted_at` | Nullable timestamp; one delete stamps the whole branch, restore keys off it |
| `PATCH /nodes/:id` | `{title?, position?}`; trim/validate title |
| `PATCH /burrows/:id` | `{viewport?}`; validated numbers |
| `DELETE /nodes/:id` | Soft-delete the node and descendants under one stamp; return `{ids}` |
| `POST /nodes/:id/restore` | Clear `deleted_at` for every row sharing the stamp |
| Reads | Filter `deleted_at IS NULL`; lineage stops at a deleted node |

## Delta table (seed; fill during the pass)

| Delta | Why | Decision |
|---|---|---|
| Expanded reader/trail | README: no separate reader | `won't` |
| Delete semantics | Hard delete needs a full stash; soft delete is reversible | `soft delete batch + restore` |
| Canvas state shape | One JSON column vs many columns | `positions` + `viewport` columns; the rest is session state |
| Pinned windows | Pin/unpin with a floating rail duplicated the card and its own text-size rules | `dropped` |
| Where canvas state lives | localStorage drifted per device and lost layout on a new client | `positions + camera on the server; folding and seen in memory` |
| Delete batch column | A second column only ever held the timestamp already in `deleted_at` | `one timestamp groups the branch` |
| Notes, reactions, note→ask | Needs notes storage + prompt context | `deferred; unscheduled` |
| File/URL/PDF import | Needs ingest/parse | `deferred; unscheduled` |
| Real Markdown/math/Mermaid content | Needs model prompt | `deferred M7`; renderer ships M5 |
| Mermaid vs DOT | Mermaid is the reference's DSL and the common LLM/code-block choice | `Mermaid` |
| highlight.js vs Shiki | Reference parity, smaller integration | `highlight.js` |
| Raw HTML | Reference sanitizes and renders some HTML/SVG; we keep it inert | `no rehype-raw` |
